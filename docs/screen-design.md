## 📱 1. 端末 (MAUI・スマートフォン)

### 1.1 前提

シェル (上部のタイトルバー + F1〜F4) と販売・会計画面のデザインは [D-23](decisions.md#d-23-端末はメニュー型のホームと-f1f4-のシェルにする)。

| 項目 | 内容 |
| --- | --- |
| 端末 | 通常のスマートフォン (Android、縦持ち・片手操作)。画面幅は 360〜430 dp を想定 |
| 画面の骨格 | シェルは、上部のタイトルバー + コンテンツ + 下部の F1〜F4 のファンクションキー。各画面は `ContentView` で、`ShellProperty` でタイトルと F キーの文言・有効を宣言する |
| ハードウェアの戻る | `OnNotifyBackAsync` で処理する。根の画面 (T-00 / T-01 / T-02) では、アプリを終了せずにバックグラウンドへ回す (`AndroidHelper.MoveTaskToBack`) |
| シェルのデザイン | タイトルバーは紺 (`BlueDarken4`) にし、機能名を左寄せ、右に「店舗-端末 担当」と未送信バッジを出す。F キーはタイトルバーと同じ紺のバーに置き、役割で色を分ける ([D-23](decisions.md#d-23-端末はメニュー型のホームと-f1f4-のシェルにする)) |
| ホームのキー | 白の平らなキーを罫線で区切り、「販売」だけ青にする |
| ナビゲーション | Smart.Navigation の `ViewId` 列挙で遷移する (`Navigator.ForwardAsync(ViewId.Xxx)`)。パラメータは `NavigationParameter` で渡す |
| 遷移のアニメーション | 各画面に `[Hierarchy(n)]` を付け、階層が深くなる遷移は右から (Forward)、浅くなる遷移は左から (Back) スライドする ([D-23](decisions.md#d-23-端末はメニュー型のホームと-f1f4-のシェルにする)) |
| ダイアログ | MauiComponents の `IDialog` (確認 / 情報 / トースト / ローディング) と、`IPopupNavigator` のポップアップ (`DialogId`)。確認と情報は、`IDialog` を実装する `SheetDialog` が `Confirm` / `Message` のシートに変換し、OS のダイアログを出さない |
| シート | ポップアップは、画面の下端に寄せたシートにする (幅いっぱい、上角が丸い。CommunityToolkit の Popup なので重ねて開ける)。一覧からの選択 (操作メニュー・絞り込み・承認者) も、OS のダイアログではなく `Select` シートで行う ([D-24](decisions.md#d-24-端末の入力は電卓と下端のシートにする)) |
| 画面の組み方 | 灰色の背景に見出し (絵文字付き) を置き、その下に幅いっぱいの白い面を並べる (`SectionPanel`、`PosSectionTemplate`)。角丸の箱 (カード) は並べず、角丸はチップ・アバター・ボタン・下端のシートだけに使う ([D-25](decisions.md#d-25-画面は平らな面で状態を示す)) |
| 金額と集計 | 主な金額 (純売上・お釣り・合計) は、白いバーに大きく出す。件数や金額の集計は、罫線で区切った表にする |
| 一覧の行 | 状態のある一覧 (取引履歴・未送信・保留・棚卸・返品明細・入荷の伝票・検品・受注) は、左端のバーと行の背景で状態を示し、区切り線で並べる。タップできる行はリップルを出す |
| 行の中の表示 | 状態は色付きのチップ (`LabelChip`)、コードは等幅、会員はイニシャルのアバターで示す |
| アイコン | 背景で使い分ける。明るい背景は色付きの絵文字、塗りつぶしの上は白い単色のアイコンか白い文字にする ([D-25](decisions.md#d-25-画面は平らな面で状態を示す)) |
| アニメーション | 金額の数え上げ、合計の背景の光り、未送信バッジの拡縮、表示時の浮き上がりを使う |
| 空の状態 | 一覧やスキャン待ちで表示するものがないときは、中央に絵文字を出す (`PosEmptyStack`)。操作の案内文は添えない |
| アプリのアイコン・スプラッシュ | 紺 (`BlueDarken4`) の背景に白いレジのグリフ (`Resources/AppIcon`、`Resources/Splash`) |
| 数値入力 | OS のソフトキーボードに依存せず、数値と番号は電卓で入力する ([D-24](decisions.md#d-24-端末の入力は電卓と下端のシートにする)) |
| スキャン | `BarcodeScanning.Native.Maui` (`BarcodeController` + `CameraView`) で、1D (JAN/EAN) と 2D (QR) を連続で読み取る |
| スキャンの用途 | 商品 JAN、会員証 (QR / バーコード)、レシート QR (返品時の取引呼び出し)、設定 QR (初期設定の画面の中で読む) |
| 設定の保存先 | `IPreferences` (`Settings`) に、サーバ URL・店舗 ID・端末 ID・登録日時・「ログイン後にシフト開設済みなら販売画面を開く」を保存する。端末のトークンは `SecureStorage` に保存する |
| 設定の入力 | サーバ URL は、印刷した設定 QR (`Key=Value` 行、`SettingParser` 互換) で読む。ペアリングコードは電卓で入れ、店舗と端末はペアリングで決まる ([D-35](decisions.md#d-35-認証は管理画面のログイン端末のトークンスタッフの-pin-にする)) |
| 通信 | `HttpService` (HttpClient + System.Text.Json、[D-28](decisions.md#d-28-端末は-viewmodel-から-service-と-usecase-を呼ぶ)) + `NetworkService` (接続確認・インジケータ・エラー通知)。`XxxRequest` / `XxxResponse` は `Pos.Contract` を参照する |
| ローカル DB | Smart.Data.Accessor + SQLite。マスタと自店在庫のキャッシュ、取引・シフト・入出金、前受金のコピー、保留、Outbox を置く ([db-design.md §6](db-design.md#-6-端末ローカル-db-sqlite-の概要)) |
| レシート | 画面表示 + 電子レシート (レシート番号を `QRCoder` で QR にして表示)。レシート画像と精算レポートのテキストは共有できる |
| オフライン | 未送信件数を、タイトルバーにバッジで出す。返品の元取引は、オフラインなら端末の取引から探す |
| オンライン限定の機能 | 会員の検索・照会・登録、他店在庫、シリアル番号の検索、入荷・受領、受注、売上照会。通信できないときは、その旨を表示する |

#### アイコン

| 場所 | 扱い |
| --- | --- |
| 明るい背景 (見出し・一覧・メニュー・メッセージ・ホームのキー・設定のボタン) | 色付きの絵文字。標準でテキスト表示になる文字 (ℹ️ ⚙️ ↩️ ▶️ ⏸️ など) には U+FE0F を付ける |
| トースト | 色付きの絵文字。OS が描き、背景の明るさが Android のバージョンとテーマで変わるため |
| 塗りつぶしのチップ、色付きのボタン (検索・番号入力・削除・ホームの販売) | 白い単色のアイコン (Material Icons) |
| シートの ✕ ✔、小さな丸ボタン (数量の増減、会員・明細の値引・希望日・支払を外す) | 白い文字 |
| カメラの画面のバー (濃い青) のメッセージ | 追加できたときは白い ✓、ほかのとき (見つからない、設定 QR でない、カメラの権限がない、登録できない) は白い ✕ で始める |
| アイコンだけの白いボタン (販売の操作)、展開のボタン | Material Icons のグリフ |
| 入出金の種別ボタン (選択で背景が濃くなる) | 選択中だけアイコンを白にする |

#### アニメーション

- 合計・お釣り・純売上は数え上げる
- 販売の合計は、変わったときに背景を光らせる
- 未送信バッジは、要確認があると拡縮を繰り返す
- 面と一覧は、表示時に下から浮き上がらせる (続けて更新する販売の明細と棚卸には付けない)

#### 空の状態

- 絵文字: 🛒 販売 / 🔍 商品 / 👤 会員 / ⏸️ 保留 / 📦 棚卸 / 📥 入荷 / 📋 受注 / 🧾 取引履歴 / ↩️ 返品
- 文言は、該当がない・取得できないときだけ添える
- オンラインで取得する画面 (会員照会、会員選択、入荷・受領、売上照会、受注一覧、受注詳細、取引履歴のシリアル番号の検索) は、取得中は結果を隠す。  
  取得できないとき (📡) は、結果の上に重ねる
- 詳細の一部をオンラインで取得するとき (会員照会の履歴、商品照会の他店在庫) は、見出しを残して「📡 取得できません」を出す

#### 数値入力

- 数量・金額・枚数・番号 (電話・郵便番号・コード・伝票番号・生年月日) は、すべて `InputNumber` ポップアップ (電卓、`NumberInputModel`) で入力する
- 入力欄は、タップで電卓を開くボタンにする
- 会計画面だけは、テンキーを画面に埋め込む
- 会員選択・商品検索の検索欄と、棚卸・検品のコード入力には、番号入力のボタン (Material Icons のダイヤルパッド) を置く
- 文字 (名前・住所・備考・検索キーワード) だけを `Entry` で入力する。  
  キーボードは欄をタップしたときだけ出す (遷移時の自動フォーカスはしない)

### 1.2 ナビゲーション構成

メニュー型 ([D-23](decisions.md#d-23-端末はメニュー型のホームと-f1f4-のシェルにする))。  
ホームに機能キーのグリッドを置き、各機能からは F1 (戻る / メニュー) でホームへ戻る。

- ホームのキーは「販売」を最上段に 2 列分の幅で置く
- 設定「ログイン後にシフト開設済みなら販売画面を開く」で販売画面を直接開ける

実線は `ViewId` による画面遷移、点線はポップアップ (`DialogId`)。  
次の遷移は図に描かない。

- 戻る遷移と、戻り先 (`WithReturnTo`) へ進む遷移
- T-20 → T-14、T-21 → T-02、T-40 → T-30、T-51 → T-90、T-90 → T-00 / T-01

`[Hierarchy(n)]` の n は、この図の深さにする (T-00 = 0、T-01 = 1、T-02 = 2、ホーム直下 = 3、その下 = 4 …)。  
遷移アニメーションは、遷移元と遷移先の n の差で決まる ([D-23](decisions.md#d-23-端末はメニュー型のホームと-f1f4-のシェルにする))。

- 親が複数ある画面は、最も深い親 + 1 にする
- T-21 → T-10 や T-93 → T-10 のように、浅い画面へ進む線は数えない

#### 共通

- 画面遷移は `ForwardAsync` だけを使う
- 戻り先を受け取る画面 (T-03 / T-11 / T-12 / T-14 / T-22 / T-62 / T-90) は、`Parameters.WithReturnTo` で受け取る (T-03 では開設後に進む画面)
- タイトルと F キーの文言・有効状態は、`shell:ShellProperty.*="{Binding ...}"` で動的に変えられる
- ポップアップの中から開くのは、次のものだけにする
  - 電卓 (`InputNumber`)
  - 理由 (`ReasonSelect`)
  - 一覧からの選択 (`Select`、`IPopupNavigator.ChooseAsync`)
  - 確認と情報のシート
  - P-13 からの値引 (P-15)
- 数量・単価・値引の値・金種の枚数は、電卓で入力する
- どの画面でもリクエストが 401 になったら、登録が解除されたと知らせて T-00 へ戻る。  
  トークンは破棄し、未送信は残す (再登録すると送る)

#### T-00 初期設定

- 設定 QR (`ApiEndPoint`) を読むと、サーバ URL を入れて電卓を開く。  
  コードを入れると、登録して初回同期する
- QR がないときは、サーバ URL とコード (電卓) を入力して F4 で登録する
- カメラの権限がなければ、バーで知らせて入力で登録する
- 読むのは QR だけにする。  
  設定 QR でない QR は知らせるだけで、欄を変えない
- 同じ QR は再読み取りしない (枠に残った QR で電卓を開き直さないように)。  
  リトライは F3 と F4 で行う
- 登録は、成功してから接続先とトークンを切り替える。  
  失敗しても今の登録のまま使える
- 初回と登録の解除の後は根の画面になり、戻るでアプリをバックグラウンドへ回す
- 登録済みの端末で開いたとき (T-90 の F2 からの再登録)
  - 登録の前に、今の登録が使えなくなることと未送信の件数を確認する
  - 未送信は、店舗コード・端末番号が同じ端末なら、その端末のものとして送る
  - F1 と戻るで T-90 に帰る (T-90 の戻り先を引き継ぐ)

#### T-01 スタッフ選択

- 開くと担当を外す (スタッフ切替や再登録の後に、前の担当を残さない)
- PIN は同期したハッシュで照合するので、オフラインでもログインできる
- PIN を 3 回間違えると、担当の選択に戻る
- F1 (設定) は T-90 を開き、戻ると T-01 に帰る

#### T-02 ホーム

- キー: 販売 (2 列幅) / 返品 / 取引履歴 / レジ開設 / 入出金 / 商品・在庫 / 会員 / 棚卸・調整 / 入荷・受領 / 受注 / 売上照会 / 設定・同期 (2 列幅)
- 「レジ開設」のキーは、開設中は「精算」になり T-51 を開く
- シフト未開設で販売 / 返品 / 入出金を選ぶと、開設へ誘導する。  
  開設後は元の画面へ進む

#### T-03 レジ開設

- サーバに開設中のシフトが残っていれば (再インストール時など)、引き継ぐ

#### T-10 販売

- 受注から会計しているときは、会員の下に受注番号のバーを出す (前受金があれば金額も)
- [⋯] は `Select` シートで、次の操作を出す
  - 取引値引 (P-15)
  - 取引値引を解除 (取引値引があるとき)
  - 配送先 (T-16)
  - 保留する (その場で保留してカートを空にする)
  - 保留を呼び出す (T-17)
  - 受注にする (T-94。受注から会計しているカートでは出さない)
  - クリア
- シリアル番号が未入力の明細があると、会計に進まない。  
  案内のあとに、その明細の P-13 を開く

#### T-11 スキャン

- 販売のモードは連続読み取りにする。  
  読むたびに明細を追加し、バーに商品名・数量・合計を出す (同じ商品は数量を +1 する)
- 販売以外のモードは、1 件読んだら呼び出し元へ戻る。  
  会員・レシートは、読んだ値を呼び出し元に渡す
- 同一コードは 2 秒間抑制する
- 検出のフラッシュは省き、バイブレーションで知らせる
- 手入力は電卓 (`InputNumber`) で行う

#### T-12 商品検索

- 画像は、結果を出した後に上から順に入れる
- 取得した画像は端末に保存し、オフラインのときはそれだけを出す

#### P-13 明細編集

- 数量・単価は、電卓 (`InputNumber`) で入力する
- 明細値引は、取引値引と同じ P-15 で入力する (定義済み / 任意額 / 任意率 + 理由)
- 承認が必要な値引は、店長 / 管理者を承認者に選び、その PIN を入れる

#### T-20 会計

- 支払方法のボタンの文言は、支払方法の `shortName` (なければ `name`) にする。  
  ポイントと前受金のボタンは出さない
- 金額ショートカットは預り金に加算し、[ちょうど] は残りの全額にする
- 支払が済むと、「残り」の行がお釣りになる
- 受注の前受金は、支払リストの先頭に置いて外せなくする (✕ を出さない)
- 画面に入るたびに、前受金の全額を先頭の支払に置き直す。  
  オンラインなら、その前に受注を再取得する (返金や他の端末の会計に追従する)
- 次のときは、案内して T-10 に戻る
  - 受注が引き渡し待ちでなくなった (キャンセル・他の端末で会計済み)
  - 前受金が合計を超える
  - 前受金の支払方法が端末にない

#### T-21 会計完了

- 返品では表題が「返品完了」になり、[次へ] でホームへ戻る (販売は T-10 の次の会計へ進む)

#### T-22 レシート

- 受注から会計した取引は、受注番号を印字する
- プレビューは、`ReceiptTextBuilder` の 32 桁のテキストを SkiaSharp で桁位置に描画した画像にする (端末のフォントが等幅でなくても崩れない)
- 共有は PNG にする (共有するときに作る)
- 描画と QR の生成はバックグラウンドのスレッド (`Task.Run`) で行い、終わるまで IDialog のインジケータを出す
- 画像は Glide を通さずに SkiaSharp の画像のまま出し、インジケータを閉じたときには表示されているようにする
- シリアル番号で探した他の店舗・端末の取引は、その店舗と端末で組み立てる
- [印刷] は、押すと「印刷は未実装です」と知らせる (Bluetooth ラインプリンタでの印刷は [backlog.md](backlog.md#-後回しにしているもの))

#### T-30 取引履歴

- 絞り込みは画面上部のボタンで選ぶ (期間: 本シフト / 本日 / 昨日 / すべて、種別)。  
  その下に、件数の内訳をチップで出す
- 行は種別・送信状態・会員のチップと、時刻・担当・支払を示す。  
  右端で明細と支払を展開する
- 送信状態は Outbox から求める (送信済 / 未送信 / 要確認)
- 最上段の検索欄でシリアル番号 (完全一致) を探すと、一覧をサーバの全店の取引に置き換える (件数は「シリアル n 件」。取得できなければ「📡 取得できません」)
- 空で検索するか期間・種別を選び直すと、端末の履歴に戻る

#### T-31 取引詳細

- 明細にシリアル番号 (S/N) を表示し、受注から会計した取引は受注番号の欄を出す
- 端末にない取引 (シリアル番号で探した他の端末の取引) は、オンラインのときにサーバから開く
- レジ係の取消は、確認のあとに店長 / 管理者を承認者に選び、その PIN を入れる (`approvedByStaffId`)
- 営業日が締め済みの取消はサーバが拒否し (`DAY_CLOSED`)、未送信の要確認に出る。  
  端末は締めの状態を持たないので、事前には知らせない
- 返品のある販売は、取消を押せなくする。  
  返品は、端末で記録した返品とサーバから取得した返品済みの数量で判断する
- オンラインなら、販売の取消の前にサーバの最新の状態で他の端末の返品を確認して知らせる。  
  その販売の返品に未送信があるときは確認しない
- 確認せずに取り消した販売に他の端末の返品があれば、サーバが拒否する (`HAS_RETURNS`)。  
  拒否された取消は、未送信の要確認に出る

#### T-42 返金

- ポイント返還は自動にする (利用ポイント分)
- 残りは、返金方法を 1 つ選ぶ
- 返金方法は元の支払方法を先頭に並べ、前受金は出さない

#### T-51 精算 / T-52 精算レポート

- 現金の内訳は、釣銭準備金・現金売上・現金返品・入金・出金・前受金の受取と返金
- 前受金の行は、現金の前受金があるシフトだけ出す
- 予想現金は、ローカルの取引・入出金・前受金から計算する (`ShiftSummaryCalculator`)。  
  前受金は、サーバが受け付けた記録を端末にコピーしたもの
- 未送信が残っていれば、警告を出す。  
  [未送信] (未送信があるとき) は T-90 を開く
- 精算レポートは、未送信がなくオンラインならサーバの集計、それ以外は端末の集計にする。  
  どちらの集計かを画面に示す
- [印刷] は T-22 と同じく、未実装と知らせる

#### T-62 会員登録・編集

- 保存すると呼び出し元へ戻る。  
  販売から開いたときは、カートに紐付ける
- 削除された会員の更新は、知らせて会員を出さずに T-61 へ戻る
- スキャン (T-11) へ行く間の入力内容は、`CustomerDraft` (Scope) に残す

#### T-70 棚卸・在庫調整

- 棚卸 / 調整のモードと入力リストは `StockContext` (Scope) に置き、スキャン画面との往復で失わない
- コードは電卓かスキャンで入力する

#### T-71 入荷・受領 / T-72 検品

- オンライン限定 ([D-16](decisions.md#d-16-入荷と店舗間移動は伝票で持つ))
- T-71 の行は、左端のバーと種類のチップ (入荷 / 移動)、仕入先か出荷店、入荷予定日か出荷日時、納品書番号 (なければ発注番号) か移動番号、商品を示す
- T-72 の明細は、左端のバーと行の背景で状態 (未確認 / 一致 / 不足 / 過剰) を示す
- T-72 では、スキャンか JAN / 商品コードで明細を選ぶか、行をタップして届いた数を電卓で入れる
- 検品中の伝票と数えた数は `ReceivingContext` (Scope) に置き、スキャン画面との往復で失わない
- 伝票にない商品は受け付けない
- 数えていない明細は、予定 (移動は出荷) の数で受け取る。  
  受領の確認で、その件数を知らせる
- 受領したら、在庫の差分同期をすぐ行う

#### T-80 売上照会

- 画面上部のボタンで、期間・範囲・集計軸を選ぶ
  - 期間: 本日 / 昨日 / 今週 / 今月
  - 範囲: 自端末 / 自店 / 全店
  - 集計軸: 支払方法別 / 時間帯別 / 担当別 / 部門別 / 日別
- 自端末は、端末別集計から自分の行を出す (集計軸は選べない)
- 合計は、日別集計の Total を使う
- 純売上は白いバーに、件数・値引・税・会員・ポイントは罫線の表に出す
- 集計軸の内訳は、純売上に対する割合のバーで示す

#### T-92 受注一覧 / T-93 受注詳細

- オンライン限定
- 取得中は結果を隠し、取得できないときは結果の上に案内を重ねる
- T-93 は、取得できなければ「📡 取得できません」だけを出す。  
  操作のキーも押せなくする
- ない受注は、知らせて T-92 へ戻る
- T-92 の状態の絞り込み: 未完了 / 入荷待ち / 引き渡し待ち / 完了 / キャンセル / すべて
- T-92 の行は、左端のバーと背景で状態を示す
- [入荷] (入荷待ちのとき) は、確認して引き渡し待ちにする
- [会計へ] (引き渡し待ちのとき) は、明細・会員・前受金をカートに入れて T-10 へ進む
  - レジ未開設なら案内する
  - 販売中の明細があれば、置き換えるか確認する
  - 単価は、売価を変更できる商品だけ受注の単価にする
- [操作] (未完了のとき) は `Select` シートで、次の操作を出す
  - 「前受金を受け取る」(前受金がないとき) か「前受金を返す」(あるとき)
  - 「受注をキャンセル」
- 前受金の受取は、支払方法 (現金・カード・QR・電子マネー) → 金額 (電卓。受注の金額まで) → 伝票番号 (要る支払方法だけ) → 確認の順に進む
- 前受金の返金は、全額を受け取った方法で返す
- 前受金の受取と返金には、レジの開設が要る
- キャンセルの理由は `ReasonSelect` で選ぶ。

- [更新] のほか、取引・シフト・在庫・受注・日次締めの書き込みの通知で自動で再読み込みする (1 秒でまとめる)
- 端末の通信状態のために、1 分ごとにも再読み込みする

#### S-10 売上集計

- 期間は営業日で指定する
- 集計単位: 日別 / 店舗別 / 時間帯別 / 端末別 / 担当別 / 支払方法別 / 税率別 / 部門別
- [売上日報を開く] は、店舗・営業日を指定して PDF を開く ([D-21](decisions.md#d-21-帳票はサーバが-pdf-にする))

#### S-20 取引一覧

- レシート番号は完全一致で探す
- S-31 から開くと、シフトで絞り込む (チップで外せる)

#### S-91 受注

- フィルタ: 受注日・店舗・状態 (既定は未完了)・種別・受注番号 / 宛名 / 電話
- 一覧の列: 受注番号・受注日時・店舗・種別と状態のチップ・お客様・電話・商品・金額 (前受金があれば下に小さく)・希望日
- 登録・変更のダイアログ: 店舗・担当・種別 (登録のみ)・会員 (選ぶと宛名と電話を補う)・宛名・電話・希望日・備考・明細 (商品を選ぶと単価は売価)
- 詳細のダイアログは、お客様・経過・明細・前受金を出す
- 詳細のダイアログの操作: [受注票 PDF] [入荷] [変更] [受注をキャンセル] [会計した取引] (S-21)
- 前受金は見るだけにする (受け取り・返すのは端末)
- 前受金があるうちは、[受注をキャンセル] を押せない

#### S-90 日次締め

- フィルタ: 営業日 (既定は直近 30 日)・店舗・状態
- 一覧の列: 営業日・店舗・状態チップ (未締め / 締め済み / 締め後の取引あり)・シフト数と未精算チップ・販売 / 返品 / 取消の件数・純売上・締め日時・締めた人
- 内容のダイアログ: 日計・締め・支払方法別・税率別・シフト一覧
- 未締めの日は、取引から集計する
- 未精算のシフトやシフトのない日は、警告して [締める] を無効にする
- [締める] / [締めを解除] は、確認のうえ実行する
- [締めを解除] は管理者だけ

#### S-42 在庫変動履歴

- 理由の列は、入荷では納品書番号、移動では移動番号を出す
- 参照の列から、取引 (S-21)・入荷 (S-45)・移動 (S-46) の詳細を開く

#### S-45 入荷

- フィルタ: 入荷予定日・店舗・仕入先・状態 (既定は入荷予定)
- 一覧の列: 登録日時・入荷予定日・店舗・仕入先・納品書番号・発注番号・状態のチップ・商品・受領日時
- 登録のダイアログ: 入荷する店舗・仕入先・納品書番号・入荷予定日・備考・明細 (在庫管理の商品。選ぶと仕入単価は原価)
- 詳細のダイアログ: 入荷・経過・明細 (予定・受領と差・仕入単価)
- 発注から作った入荷予定は、詳細のダイアログの発注番号から S-48 の詳細を開く
- 詳細のダイアログの操作
  - [受領] (担当と届いた数を確認する)
  - [入荷をキャンセル] (発注から作った入荷予定は、発注もキャンセルになる)

#### S-46 店舗間移動

- フィルタ: 店舗 (出荷店か入荷店)・状態 (既定は未受領)
- 一覧の列: 移動番号・依頼日時・出荷店・入荷店・状態のチップ・商品・出荷日時・受領日時
- 依頼のダイアログ: 出荷店・入荷店・備考・明細
- 詳細のダイアログ: 移動・経過・明細 (数量・受領と差)
- 詳細のダイアログの操作
  - [出荷] (担当を選び、依頼の数で出す)
  - [受領] (担当と届いた数)
  - [移動をキャンセル]

#### S-48 発注

- フィルタ: 希望納期・店舗・仕入先・状態 (既定は未完了)
- 一覧の列: 発注番号・登録日時・希望納期・店舗・仕入先・状態のチップ・商品・金額
- 登録のダイアログ: 店舗・仕入先・希望納期・備考・明細 (在庫管理の商品。選ぶと仕入単価は原価)
- 詳細のダイアログ: 発注・経過・明細 (発注・入荷と差・仕入単価・金額)
- 経過は、登録・発注の日時と発注した人、入荷予定を出す。  
  「入荷予定を開く」で S-45 の詳細を開く
- 詳細のダイアログの操作
  - [発注書 PDF]
  - [発注をキャンセル] (未完了のとき)
  - [変更] [発注] (下書きのとき。[発注] は確認のうえ入荷予定を作る)

#### S-51 商品編集

- 画像は JPEG / PNG で、2 MB まで
- `ProductForm` の項目: コード・JAN・名称・かな・メーカー・型番・部門・種別・価格・内税/外税・税率・原価・還元率・シリアル要・在庫管理・売価変更可・単位・販売可否
- [保存] は、商品を保存した後に画像を反映する
- キャンセルすると、選んだ画像も破棄する

#### S-52 商品 CSV 取込

- プレビューは、新規 / 更新 / 変更なし / エラーの件数と、行ごとの結果チップ・誤りの文言を出す
- 変更のない行は、切り替えで表示する
- [取込] は、誤りがなく変更のある行があるときだけ使える
- 取り込んだら、件数を通知して一覧を再読み込みする

#### S-71 レジ端末

- 登録の列は、未登録 / 登録済み / 解除を出す。  
  登録済みは日時を出し、機種はツールチップで出す
- [設定 QR] は、S-73 を新しいタブで開く
- [ペアリングコードを発行] は、6 桁のコードと有効期限をダイアログで出す

#### S-73 設定 QR

- [印刷] では、ボタンと注意を印刷しない
- 接続先は `Terminal:ApiEndPoint` にし、なければ管理画面を開いた URL にする
- 接続先が localhost なら、端末から届かないと知らせる

### 2.4 共通 UI パターン

| パターン | 内容 |
| --- | --- |
| 一覧 | 上部に検索・フィルタ (`MudTextField` / `MudSelect` / `MudDateRangePicker`)、その下に `MudDataGrid` (`ServerData` + `MudDataGridPager`、列ソートはサーバ側)。マスタは全件の `MudTable` |
| 検索条件 | ページ内で保持する。他画面からのリンクだけクエリで受ける (`transactions?id=` / `?shiftId=`、`orders?id=`、`inventory/receipts?id=`、`inventory/transfers?id=`、`inventory/purchase-orders?id=`、`inventory/changes?productId=`、`daily-closings?unclosed=true`) |
| 見出しの絵文字 | ページ見出しは §2.2 のグループと同じ絵文字にする (受注 📋、日次締め 🗓️、発注 📝 は画面ごとの絵文字) |
| 状態のチップ | `StatusChip` (`ViewHelper` の文言 + 色 + 白い単色のアイコン)。塗りつぶしの上では色付きの絵文字が背景に溶けるため、アイコンは白い単色にする ([D-25](decisions.md#d-25-画面は平らな面で状態を示す)) |
| 件数のバッジ | 見出しの右に縦中央で並べた `MudBadge` と、タブの `BadgeData` |
| KPI | `MudPaper` + `MudIcon` のカード ([D-22](decisions.md#d-22-管理画面はサーバに同居させservice-を呼ぶ)) |
| 編集ダイアログ | 新規と編集で同じダイアログ (`{Xxx}EditDialog` + `{Xxx}Form` + FluentValidation) を使う。保存は `Version` で楽観ロックし、競合 (`DataWriteStatus.VersionMismatch`) なら Snackbar で「他で更新されています」と知らせて再読み込みを促す |
| 削除 | `DialogService.ShowConfirm` で確認して論理削除し、一覧に「削除済みを表示」のトグルを置く。使用中 (`DataWriteStatus.InUse`) は Snackbar で知らせる |
| 店舗フィルタ | 売上・取引・精算・在庫の各一覧は、店舗セレクタを持つ (「全店舗」可)。選択は、ページ間で共有するスコープドサービスに保持する |
| エラー表示 | 失敗の種類で出し方を分ける。例外はどれもサーバのログに記録する |
| 出力 | 売上集計・商品別売上・商品は CSV のダウンロード (`/api/v1/.../csv`)、帳票 (売上日報・精算レポート・レシートの控え・受注票・発注書) は PDF (`/api/v1/.../pdf`、OysterReport、[D-21](decisions.md#d-21-帳票はサーバが-pdf-にする))。どちらも `MudButton Href` で開く |

#### 状態のチップ

`StatusChip` の状態は、完了 / 取消 / 販売 / 返品 / 開設中 / 精算済み / 未締め / 締め済み / 締め後の取引あり / 取り寄せ / 取り置き / 入荷待ち / 引き渡し待ち / キャンセル / 入荷予定 / 出荷待ち / 受領待ち / 受領済み / 有効 / 停止 / 削除済み / マイナス / 欠品 / 通信中 など。

#### エラー表示

| 失敗 | 表示 |
| --- | --- |

| ページの書き込みの失敗 | バナーと Snackbar |
