# 文書 (docs/、README)

## 内容

- `docs/` は人向けの設計文書にし、現状 (何を・なぜ) だけを書く。どう書くべきかの規則は規則ファイルに置く
- `docs/decisions.md` には、機能とアーキテクチャについて決めた方針 (どうあるべきか、何をサポートするか、その理由) だけを書き、検討した案と進め方は書かない
- 設計文書には実装済みの内容だけを書き、作っていない機能と今後の検討事項は `docs/backlog.md` に置く
- 実装が変わるたびに古くなる数 (テストの件数、クラスの数、初期データの件数) は書かない。列挙するときは漏れのないようにするか、代表を挙げて「など」で結ぶ
- 実装の計画 (フェーズのチェックリスト) は作っている間だけ置き、作り終えたら消して、残った項目を `docs/backlog.md` に移す

## 形式

- 章 (`##`) の見出しだけ先頭に絵文字を付ける (`###` 以下には付けない)
- 見出しの絵文字は、標準で絵文字の形になるもの (U+FE0F の要らないもの) にする (アンカーに異体字セレクタが入らないように)
- 見出しを変えたら、その見出しへのリンクのアンカーも直す
- 表のチェックや可否は絵文字 (✅ など) で示す
- Markdown は 1 行 1 文にし、「。」の後に 2 スペースを置いて改行する (表、見出し、コードは除く)
- 箇条書きは最後の文に「。」を付けず、続きの行は本文の位置に字下げする
- 括弧の中の補足は「。」で区切って同じ行に続けてよい (箇条書きと段落のどちらも)
- 列挙、項目と値の組、条件ごとの扱いは、文で続けずに箇条書きか表にする
- 表のセルは短くし、長い説明は表の下の箇条書きに出す
