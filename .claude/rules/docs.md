# 文書と規則

## 文書

- `docs/` は人間向けの設計文書にし、現状 (何を・なぜ) だけを書く。どう書くべきかの規則は規則ファイルに置く
- `docs/decisions.md` には、機能とアーキテクチャについて決めた方針 (どうあるべきか、何をサポートするか、その理由) だけを書く。過去の形や経緯、検討した案、後回しにしたこと、進め方は書かない
- 文書に経緯と日付は書かない (過去の形は git の履歴で追う)
- 設計文書には実装済みの内容だけを書き、作っていない機能と今後の検討事項は `docs/backlog.md` に置く
- 実装が変わるたびに古くなる数 (テストの件数、クラスの数) は書かない。列挙するときは漏れのないようにするか、代表を挙げて「など」で結ぶ
- 実装の計画 (フェーズのチェックリスト) は作っている間だけ置き、作り終えたら消して、残った項目を `docs/backlog.md` に移す
- README は概要 (数行)、主要な画面の画像と一言の説明、`docs/` の文書へのリンクだけにする (画面 ID や手順、AI 向けの規則 (`AGENTS.md`、`.claude/`) は載せない)
- 人が読む文書 (README、`docs/`) は見てわかりやすくする。章 (`##`) の見出しは先頭に絵文字を付け、表のチェックや可否は絵文字 (✅ など) で示す
- 見出しの絵文字は、標準で絵文字の形になるもの (U+FE0F の要らないもの) にする (アンカーに異体字セレクタが入らないように)。見出しを変えたら、その見出しへのリンクのアンカーも直す
- `docs/` と README の Markdown は 1 行 1 文にし、「。」の後に 2 スペースを置いて改行する (表、見出し、コードは除く)
- 箇条書きは最後の文に「。」を付けず、続きの行は本文の位置に字下げする。括弧の中の補足は「。」で区切って同じ行に続けてよい
- 文の中の引用 (「…」と) には「。」を入れない

## 規則

- AI 向けの規則は `AGENTS.md` (すべてのエージェントが読む全体の書き方・検証・進め方) と `.claude/rules/` (コードの書き方。`common.md` は常時読み込み、他は `paths` で領域別) に置く
- AI が読むもの (`AGENTS.md`、`.claude/`) は AI にとっての読みやすさを優先し、人向けの飾り (見出しの絵文字など) は付けない
- 繰り返す手順 (検証、README の画像、エミュレータでの確認) は `.claude/skills/` にスクリプトと一緒に置く。環境に固有の値 (機器、ポート) は skills に書かず、引数で受ける
- 規則ファイルは 1 項目 1 行 1 話題にする (表とコード例は除く)。文書の「。」+ 2 スペースの改行は適用しない
- 例の列挙は「、」、択一は「 / 」で区切る
