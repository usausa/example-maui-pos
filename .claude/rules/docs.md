# 文書と規則

## 文書

- `docs/` は人間向けの設計文書にし、現状 (何を・なぜ) だけを書く。どう書くべきかの規則は規則ファイルに置く
- 経緯と設計判断は `docs/decisions.md` にだけ書き、日付は書かない (`implementation-plan.md` は計画と進捗のチェックだけ)
- README は概要 (数行)、主要な画面の画像と一言の説明、文書へのリンクだけにする (画面 ID や手順は書かない)
- `docs/` と README の Markdown は 1 行 1 文にし、「。」の後に 2 スペースを置いて改行する (表、見出し、コードは除く)
- 箇条書きは最後の文に「。」を付けず、続きの行は本文の位置に字下げする。括弧の中の補足は「。」で区切って同じ行に続けてよい
- 文の中の引用 (「…」と) には「。」を入れない

## 規則

- AI 向けの規則は `AGENTS.md` (すべてのエージェントが読む全体の書き方・検証・進め方) と `.claude/rules/` (コードの書き方。`common.md` は常時読み込み、他は `paths` で領域別) に置く
- 繰り返す手順 (検証、README の画像、エミュレータでの確認) は `.claude/skills/` にスクリプトと一緒に置く。環境に固有の値 (機器、ポート) は skills に書かず、引数で受ける
- 規則ファイルは 1 項目 1 行 1 話題にする (表とコード例は除く)。文書の「。」+ 2 スペースの改行は適用しない
- 例の列挙は「、」、択一は「 / 」で区切る
